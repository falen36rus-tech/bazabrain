# База знаний 1С

Собственный портал на Django для инструкций по вашей конфигурации 1С. При первом запуске создаётся дерево с правками из документа «Дерево 2.docx»: 11 корневых разделов, 46 вложенных разделов и 290 страниц. Страницы пока без текста; инструкции, скриншоты, вложения и ссылки на Rutube добавляет администратор.

## Что уже работает

- Дерево вложенных разделов слева и статья справа; адаптивный интерфейс.
- Переключатель 18 сервисов рядом с названием, отдельное дерево инструкций для каждого. Для 1С есть вкладки «Разделы 1С» с исходным деревом и «Дисциплины» с семью направлениями. Переходы между страницами плавно анимируются в браузерах с поддержкой View Transitions.
- Материалы с аудиторией «Открыто без входа» доступны без регистрации; существующие страницы «Все сотрудники» остаются закрытыми от гостей. Чтобы показать статью без входа, отметьте открытый доступ и для статьи, и для всех родительских разделов. Пользователю без роли редактирование недоступно. Руководителю со статусом персонала и группой «Руководители» администратор назначает ответственный раздел; он редактирует этот раздел и статьи внутри него. Суперпользователь управляет всем. После выхода из панели управления открывается публичная главная страница с кнопкой входа.
- Поиск по заголовку, описанию и тексту всех блоков. На PostgreSQL используются русская морфология и сравнение похожих заголовков; в локальной SQLite-демонстрации — поиск без учёта регистра.
- Группы «Руководители», «Разработчики» и «Редакторы», создаваемые при миграции. Для каждого раздела и статьи задаётся аудитория. Закрытое содержимое исключается из страниц, дерева, поиска, подсказок и скачивания файлов. Редакторы видят все разделы, но черновики на обычном сайте не показываются.
- Статьи из блоков: подзаголовок, текст, примечание, скриншот, видео Rutube. Блоки позволяют вставлять изображения и видео между абзацами; отдельное поле ставит видео сразу под названием статьи. Дополнительные файлы прикрепляются к статье.
- В панели управления поля описания раздела, краткого описания статьи и текстовых блоков имеют панель оформления: жирный, курсив, подчёркивание, размер и выравнивание. Для крупного названия статьи предусмотрены отдельные настройки размера, начертания и выравнивания. Текст названия для дерева и поиска остаётся обычным.
- В блоке статьи можно добавить одно фото или сразу несколько через «Добавить ещё фото». Фото отображаются сразу под текстом блока; для группы доступно перелистывание. Редактор задаёт ширину на странице от 25% до 100%. При открытии доступны стрелки, увеличение колёсиком мыши и перетаскивание увеличенного изображения левой кнопкой мыши. Сохранённый файл виден в форме редактирования.
- В редакторе достаточно вставить ссылку на Rutube. Приложение принимает только ссылки на конкретное видео `rutube.ru` и формирует iframe без вставки произвольного HTML.
- Черновики, публикация и панель управления материалами на `/admin/`. У статей, вложенных блоков и разделов есть история правок с восстановлением предыдущих версий.

## Локальная демонстрация

Нужен Python 3.12 или новее. В каталоге проекта:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
$env:DJANGO_DEBUG = "1"
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py createsuperuser
.venv\Scripts\python manage.py runserver
```

Откройте `http://127.0.0.1:8000/` и войдите под созданной учётной записью. В `/admin/` откройте существующую статью из импортированного дерева и добавьте блоки в нужном порядке. Новые разделы и статьи также можно создавать там. При создании редактора суперпользователь создаёт ему отдельную учётную запись, отмечает «Статус персонала» и добавляет в группу «Редакторы». Эта группа может создавать и менять все разделы и статьи, а также их блоки и файлы, но не управляет пользователями и не удаляет разделы и статьи. В обычном разделе «История» редактор видит прошлые версии и может восстановить их. Всем вошедшим сотрудникам доступны материалы с аудиторией «Все сотрудники»; закрытые разделы требуют соответствующей группы. Суперпользователь имеет доступ ко всем аудиториям.

Для руководителя создайте учётную запись, отметьте «Статус персонала», добавьте её в группу «Руководители» и назначьте пользователя в поле «Ответственный руководитель» нужного раздела. Руководитель сможет менять этот раздел и его дочерние разделы, добавлять и менять статьи в них; другие разделы в панели управления ему недоступны. Обычному пользователю можно создать учётную запись без статуса персонала и добавить группу «Пользователи базы знаний»; права редактирования у неё отсутствуют. Открытые материалы доступны и без учётной записи. Новые сервисы наполняются в панели управления через поле «Сервис» у раздела; дисциплины 1С уже созданы и готовы для дочерних разделов и статей.

Исходная версия дерева сохранена в `kb/data/tree_2026_10_01.json`, а исправленная — в `kb/data/tree_2026_10_01_revision.json`. Миграция `0004_initial_document_tree` создаёт исходную структуру, после чего `0005_revised_document_tree` добавляет три папки и переносит под них страницы в пунктах 3, 4 и 5. При обновлении существующей установки примените `python manage.py migrate`. Дальнейшие изменения названий и материалов через редактор не перезаписываются при перезапуске сервера.

## Размещение на сервере

Проект подготовлен к работе на Ubuntu с Docker Compose и PostgreSQL. Скопируйте `.env.example` в `.env`, задайте длинные случайные значения `DJANGO_SECRET_KEY` и `POSTGRES_PASSWORD`, домен в `DJANGO_ALLOWED_HOSTS` (сохраните также `127.0.0.1` для локальной проверки) и HTTPS-адрес в `DJANGO_CSRF_TRUSTED_ORIGINS`. Затем:

```bash
docker compose up -d --build
docker compose exec web python manage.py createsuperuser
docker compose exec web python manage.py createinitialrevisions
```

Приложение слушает только `127.0.0.1:8000`; перед ним нужен корпоративный reverse proxy с HTTPS и заголовком `X-Forwarded-Proto: https`. Запросы к `/private/` должны идти через Django. Каталог `private_media` нельзя публиковать веб-сервером напрямую. Для резервного копирования сохраняйте одновременно базу PostgreSQL и том `uploads`.

Авторизация сейчас основана на учётных записях Django. Подключение AD/LDAP/SSO возможно после уточнения принятого в компании способа входа. Перед рабочим запуском также нужно решить, где будут размещены резервные копии и кто сможет создавать пользователей.

Видео «Только по ссылке» на Rutube содержит ключ доступа в адресе плеера. Просмотр страницы защищён ролью в базе, но обладатель такой ссылки может открыть видео вне портала; конфиденциальные записи следует размещать с учётом этого ограничения.

## Совместная работа и выпуск обновлений

Программный код, шаблоны, настройки и миграции хранятся в GitHub-репозитории `falen36rus-tech/bazabrain`. База PostgreSQL, пользовательские учётные записи, тексты статей и загруженные файлы **не помещаются в Git**. Несколько редакторов меняют материалы прямо на рабочем сайте через `/admin/`; изменения видны сразу после сохранения и сохраняются в истории правок. Изменения кода, подготовленные в этом рабочем пространстве, отправляются в GitHub отдельной веткой и вливаются в `main` после проверки.

Новая версия сайта выпускается вручную: в GitHub откройте **Actions → Выпустить обновление → Run workflow**, выберите `main`. Перед выпуском повторно запускаются проверки; при успехе указатель `production` переводится на проверенный коммит. Серверный скрипт `deploy/update.sh` проверяет `production` по расписанию и применяет только новый выпуск. Он сохраняет копии PostgreSQL и загруженных файлов перед сменой версии, обновляет код и контейнеры, применяет миграции и отмечает успешно установленный коммит. Ошибка не помечается успешным выпуском, поэтому следующая попытка повторит установку. Резервные копии хранятся вне Git-репозитория; настройте их отдельное копирование и срок хранения.

Если репозиторий открыт всем, Ubuntu-сервер может клонировать его по HTTPS без ключа. Если репозиторий остаётся закрытым, создайте на сервере отдельный SSH-ключ и добавьте **только его открытый ключ** в **GitHub → Settings → Deploy keys → Add deploy key** без **Allow write access**. После первого ручного выпуска клонируйте ветку `production` на сервер, задайте `.env`, запустите `bash deploy/update.sh` и создайте суперпользователя. Для автоматического обновления настройте `cron` или таймер systemd на запуск `bash /путь/к/bazabrain/deploy/update.sh` каждые пять минут от пользователя, которому доступны Git, Docker Compose, файл `.env` и каталог резервных копий. Скрипт не перезаписывает локальные правки кода на сервере и не применяет расходящуюся историю Git.
